# Reflection

Completing Laboratory 1: Welcome to the Cloud gave me my first hands-on experience working inside a Linux environment through KillerCoda. Before this activity, I only had a basic idea of what cloud computing involved, but going through the onboarding process as a "Junior Cloud Infrastructure Engineer Trainee" helped me understand what real cloud engineers actually do on a daily basis — from managing user accounts to documenting technical work.

One of the most valuable things I learned was how to navigate the Linux command line and use commands like `whoami`, `pwd`, `lscpu`, `free -h`, and `df -h` to gather system information. At first, some of the commands felt unfamiliar, especially setting up a new user account with sudo privileges, but repeating the steps helped me get more comfortable with the terminal.

I also learned the importance of organizing files properly, both in Linux (using `mkdir -p` to build a clear folder structure) and in GitHub (structuring my repository with a root README and separate laboratory folders). This made me realize that documentation is not just an extra requirement — it's actually a core skill for any IT professional, since clear documentation makes work easier to review, share, and build on later.

Overall, this activity helped me build the foundation of my Cloud Computing Portfolio and gave me more confidence in using Linux and Git/GitHub together. It also showed me that being a cloud engineer isn't just about knowing cloud platforms — it starts with strong fundamentals in operating systems, file management, and clear technical writing.
